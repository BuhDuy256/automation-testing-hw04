This report follows the FIT@HCMUS AI Audit Report template. ## 5. Conclusion – When should AI be used (or not)?

AI is useful for decomposing an authoritative API specification into candidate partitions, state checks, security ideas, schema assertions, structured bug reports, and reproducible automation. It must remain an auditable assistant rather than an undocumented source of requirements or human approval. AI should not invent HTTP statuses, validation rules, response schemas, confirmed bugs, execution evidence, or green CI compliance when authoritative evidence says otherwise. Human review is necessary to separate official contract cases from exploratory robustness cases, isolate faults, define deterministic inputs, reject duplicates, constrain security claims, and expose assignment conflicts. In this audit, both CI demonstration workflows are deliberately classified INCOMPLETE even though their real sample runs work correctly, because a one-case green run does not prove that all canonical cases pass. The FR-08 phase adds two further lessons. First, capturing the exact prompt, tool and timestamp at generation time turned the audit from a reconstruction problem into a reading problem: every FR-08 row quotes a prompt that existed before the output. Second, a passing test is not automatically evidence: because the implementation never derives the checkout total from the cart, the FR-08 cases whose client value happened to equal the cart total pass without proving anything, and that limitation is recorded next to the results instead of being presented as coverage.
