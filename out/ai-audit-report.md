## 5. Conclusion – When should AI be used (or not)?

AI is useful for decomposing an authoritative API specification into candidate partitions, state checks, security ideas, and schema assertions. It must remain an auditable assistant rather than an undocumented source of requirements. AI should not be used to invent HTTP statuses, validation rules, response schemas, or confirmed bugs when the specification is silent. Human review is necessary to separate official contract cases from exploratory robustness cases, isolate faults, define deterministic inputs, and reject duplicates or non-test procedures. In this audit, human review accepted 21 artifacts as-is, corrected 16 incomplete artifacts, and rejected 10 artifacts as invalid for the reviewed executable suite.
